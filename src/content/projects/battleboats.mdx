Two Uno32 boards play a turn-based game against each other over a crossed UART
link. The game itself is the easy part; the parts worth writing up are the link
and the trust problem.

**The protocol.** Messages are framed in an NMEA-like format with an XOR
checksum over the payload, decoded a character at a time by a state machine
rather than buffered and parsed whole. That matters on a microcontroller
receiving one character per interrupt: the decoder holds a few bytes of state
instead of a whole message buffer, and a corrupted frame is rejected at the
checksum rather than producing a half-valid move. Five message types cover
challenge, accept, reveal, shot and result.

**The trust problem.** Whoever moves first has an advantage, and neither board
can watch the other generate a random number. Turn order is settled with a
commitment scheme: each side commits to a hash of its secret, both commitments
are exchanged, then both secrets are revealed and combined into the coin flip.
Because each side committed before seeing the other's secret, neither can choose
a secret that steers the outcome, and a revealed secret that does not match its
commitment is detected as cheating rather than silently accepted.

**Framing and pacing.** The link runs at one character per timer tick against a
100 Hz timer, transmitting every tenth tick, so the protocol had to survive
being spread across time rather than arriving as whole messages. The decoder is
built for that: each character advances a state machine through frame start,
payload, checksum and terminator, and an unexpected character at any state
resets cleanly to hunting for the next frame start instead of corrupting the
game. Host-side Python tools drive the same protocol from a PC, which is what
made the link testable without a second board on the bench.

**Game logic.** A top-level state machine drives negotiation, move submission
and win detection across seven states: start, challenging, accepting,
attacking, defending, waiting to send, and the end screen. Board state tracks
both fields on a 6 by 10 grid with four boat classes of three to six cells,
per-boat life tracking, random placement with collision avoidance, and guess
generation for the opposing side. Both fields render side by side on a 128 by
64 display, showing own boats and hits against unknown squares on the
opponent's field, updated as results come back over the wire.

**Ownership.** Solo build: protocol, negotiation, game logic, field management
and display.
