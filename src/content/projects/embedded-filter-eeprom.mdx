A mixed-signal path on a PIC32: analog in, filtered, analog out, with the filter
itself treated as data rather than as code.

**The signal path.** A four-channel scanning converter fills a circular buffer
from its interrupt handler. A 32-tap FIR convolution with signed integer weights
runs over that buffer, and the result drives an external converter over SPI,
synchronized to the conversion rate so the output cadence is set by the sampler
rather than by the main loop.

**Why the coefficients are external.** Compiled-in coefficients mean a rebuild
and a reflash to change filter behavior. Here the coefficient banks live in an
external EEPROM over I2C, with byte and page-level access and write-complete
polling, so a bank survives power cycling and can be swapped without touching
the firmware image. A checksummed packet protocol over the serial link updates
them at runtime, with a packet queue so protocol handling does not stall the
sampling path.

**The protocol.** Coefficient updates arrive over a checksummed packet protocol
with framing, length, id, payload and an iterative checksum, decoded into a
packet queue so protocol handling never stalls the sampling path. Endianness is
converted explicitly at the boundary, which is the kind of detail that either
gets designed in or gets discovered as a corrupted filter three weeks later.

**Why the buffer is circular.** The converter fills a circular buffer from its
interrupt handler while the convolution reads behind it, so the filter always
operates on the most recent 32 samples without either side blocking the other.
The output converter is fed at the conversion rate, making the whole path
deterministic from sample in to sample out.

Front-panel switches select the active input channel, switch between two filter
banks, and choose between absolute-value and peak-to-peak display modes, so the
effect of a coefficient change is visible immediately on the hardware.

**Ownership.** Solo build: sampling engine, filter, EEPROM driver, protocol and
display.
